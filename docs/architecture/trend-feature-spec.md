# Specification: Trend canvas with pens (SemiPlot)

A single prioritized list of requirements for the trend visualization component. The functional reference is MasterSCADA "MasterTrend" (adapted to the SemiPlot scope). The data source is **always PostgreSQL**. Priorities: **MUST** (without it the product does not solve the user's task), **SHOULD** (important, but a workaround is acceptable at the start), **NICE** (an improvement, can be deferred).

Acceptance-criterion labels: "UI" — verified in the running application; "Core/test" — verified by a unit test on renderer-agnostic logic; "DB" — verified against a real PostgreSQL connection.

---

## 1. Time axis and navigation

### TM-1 — Continuous time canvas (MUST)
**Definition.** A single horizontal time axis, shared by all elements that operate on time (the plot window, the minimap, the hover readout, the future value table). All plottables are pinned to one bottom X axis; a change of the time window applies to all elements at once. Time is displayed in the local time zone.
**Acceptance.** UI: when the window changes, all pens and overlays shift synchronously, with no desync between pens. Core/test: every series uses the single bottom axis (the shared-X invariant in `ChartAxisBinder`). UI: axis labels are local time via the single `LocalTimeAxis`.

### TM-2 — Time zoom with the mouse wheel (MUST)
**Definition.** Scrolling the wheel over the plot window scales the time window relative to the cursor position. Zoom is quantized onto a 1.25 ladder so that an in/out round-trip produces no drift of the bounds.
**Acceptance.** Core/test: `TrendNavigationModel` — a zoom-in→zoom-out sequence returns the original `From/To` without accumulated error. UI: the wheel changes the scale, the center anchored to the cursor.

### TM-3 — Pan (shift the time window) (MUST)
**Definition.** Dragging the plot window with the mouse and/or horizontal navigation shifts the visible interval in time without changing the scale. Window clamps: width 1 s … 1 year; `From ≥ FirstSample`.
**Acceptance.** Core/test: pan does not go past `FirstSample` or beyond the width limits. UI: a drag shifts the window, the pens stay in place by value.

### TM-4 — Minimap (horizontal navigator) (MUST)
**Definition.** An overview strip across the entire available archive extent with the current window highlighted. A click/drag on the minimap moves the window (recentering on a fraction of the extent). The extent is pulled from the data provider.
**Acceptance.** Core/test: `MinimapGeometry` — extent+window → (startFraction, widthFraction) and back fraction→time without loss of precision. UI: the highlight tracks every window change; a click on the minimap moves the window.

### TM-5 — Undo/Redo of time navigation (SHOULD)
**Definition.** Undo/redo of the most recent horizontal shift and scale operations.
**Acceptance.** UI: after a series of pan/zoom operations the undo button returns the previous bounds and redo restores them; the stack survives several steps.

### TM-6 — Quick interval selection and exact bound entry (SHOULD)
**Definition.** A date-time panel: calendar/time for the left and right bounds, a quick-interval picker (last hour/day/week, etc.), a "go to data now" button.
**Acceptance.** UI: entering explicit dates sets the window exactly; a quick interval sets the corresponding width ending at "now".

### TM-7 — Navigation hotkeys (NICE)
**Definition.** Ctrl+Left/Right — shift in time; Ctrl+Up/Down — shift vertically.
**Acceptance.** UI: the keys perform the corresponding shift when the canvas has focus.

### TM-8 — Linking several trends by time (NICE)
**Definition.** Several canvases synchronize on the time scale: changing the window in one changes the windows of the linked ones.
**Acceptance.** UI: with two linked canvases, a pan/zoom in one is repeated in the other.

## 2. Y axes and pen scales (multi-axis)

### AY-1 — Multiple Y axes (MUST)
**Definition.** Several independent vertical axes; pens are scaled and positioned along Y independently of each other. Axes are placed deterministically (in order of the first appearance of an axis key), alternating left/right sides.
**Acceptance.** Core/test: `PenScaleModel.Compute` for pens with different axis keys returns one `PenScale` per key, with a stable order. UI: `ChartAxisBinder` renders the first axis as the built-in left axis, then alternates Add(Right/Left)Axis.

### AY-2 — Per-pen scale ("each on its own axis") (MUST)
**Definition.** The canonical case "N lines, each with its own min..max scale" must work literally: each such pen gets its own axis with its own range, rather than sharing a common min/max with others. The axis key (`AxisKey`) must be controllable, not hard-wired to the pen's group.
**Acceptance.** Core/test: when each pen is assigned a unique `AxisKey`, the model builds N axes with independent ranges. UI: after loading the "gas lines" catalog, the operator sees each line on its own scale (this fixes the current discrepancy where all 10 share one axis).
**Note.** Closes gap (b)4/(b)5 of the current state: `PenScaleSettings.AxisKey` cannot be overridden at runtime, and the catalog places all lines into one group.

### AY-3 — Manual min/max for an axis (MUST)
**Definition.** `Manual` mode: fixed `ManualMin/ManualMax` for an axis; on swapped bounds — auto-swap. Bound editing is available from the UI (a click in the upper zone of the axis = MAX, in the lower zone = MIN, inline editor).
**Acceptance.** Core/test: `ScaleMode.Manual` returns exactly the given bounds; swapped input is swapped back. UI: a click in an axis zone opens the editor, and entry applies the bounds immediately.

### AY-4 — Autoscale over all data (MUST)
**Definition.** `Auto` mode: min/max over the pen's whole envelope with 5% padding; a flat range → ±0.5. A one-shot autofit via a button/double-click on the axis.
**Acceptance.** Core/test: `ScaleMode.Auto` — the bounds span min..max with padding; a flat range gives ±0.5. UI: a double-click on the axis fits the pen in full.

### AY-5 — Autoscale to the visible window (SHOULD)
**Definition.** `AutoscaleToWindow` mode: min/max only over the columns inside the current `[windowStart, windowEnd]`. It must be **available from the UI** (toggle/command), not only modeled in Core.
**Acceptance.** Core/test: the mode computes bounds only over the points in the window. UI: a command/toggle switches the axis into this mode, and the bounds are recomputed when the window changes.
**Note.** Closes gap (b)3: the mode exists in Core but is not wired to the interface.

### AY-6 — Logarithmic scale (SHOULD)
**Definition.** A log axis mode (Log10/Ln/arbitrary base — at minimum Log10). Values ≤ 0 are sanitized (dropped/clamped), and there is a default range on empty data. The mode must be **available from the UI and actually change the axis type in the render**, not merely clamp linear limits.
**Acceptance.** Core/test: `IsLogarithmic` drops ≤ 0 and yields correct bounds. UI: a toggle enables the log axis, and the scale is visually logarithmic (log ticks/grid), not linear with a clamp.
**Note.** Closes gap (b)2: the model supports log, but the UI has no toggle and `ChartAxisBinder` only does a linear `SetLimitsY`.

### AY-7 — Position binding and vertical-scale presets (NICE)
**Definition.** Axis binding (Left/Right/Center/Free) with a percentage offset, plus user presets for the vertical scale in percent (add/edit/delete, apply to a pen or to all).
**Acceptance.** UI: changing the position moves the axis; selecting a preset applies the interval to the target pen.

## 3. Pens

### PN-1 — Pen model and Y layer (MUST)
**Definition.** A pen: `PenId`, `Name`, `Group`, `Color`, `LineStyle`, axis key. A pen's history is a `PenHistoryEnvelope` (parallel `Timestamps/Min/Max/Center`, strictly increasing timestamps, NaN = gap). Render: `Scatter(Center)` + a `FillY(Min/Max)` band; the band is hidden where Min==Max.
**Acceptance.** Core/test: the envelope constructor throws on unequal lengths and non-increasing timestamps; NaN breaks the line. UI: the band is drawn only where Min≠Max.

### PN-2 — Resize a pen's Y layer (MUST)
**Definition.** The user can compress/stretch a pen vertically (change the visible Y range of a specific pen/axis) independently of the others — with the mouse and/or bound controls.
**Acceptance.** UI: the resize operation changes the Y bounds of the target pen without affecting the others; the result matches the given range. Core/test: recomputing `PenScale` for one axis does not change the others.

### PN-3 — Set a pen's min/max (MUST)
**Definition.** Direct entry of the upper/lower Y bound for a pen (via the pen's axis/layer). See AY-3.
**Acceptance.** UI: entering `Y-top`/`Y-bottom` applies to the pen immediately; the values persist until the next mode change.

### PN-4 — Enable/disable a pen (visibility) (MUST)
**Definition.** A pen can be hidden/shown (a checkbox in the legend, two-way sync with the visibility flag). A hidden pen is not drawn and does not participate in the hover readout.
**Acceptance.** UI: toggling visibility in the legend removes/restores the pen and its band; the flag is synchronized between the legend and the chart without looping (guard).

### PN-5 — Color and line style (MUST)
**Definition.** A pen's color and line style: interpolated (a straight line between points) and stepped (Stepped). Style is mapped to the render via `PenLineStyleMap`.
**Acceptance.** UI: changing the color recolors the line; Stepped draws steps, Interpolated draws straight segments.

### PN-6 — Active pen (MUST)
**Definition.** One pen can be "active"; delta measurements (CU-3) and context operations apply to the active pen. The active pen is chosen from the legend / by click.
**Acceptance.** UI: selecting the active pen is reflected in the legend; Δy is measured against the active pen.

### PN-7 — Line construction methods: Bézier and bad values (SHOULD)
**Definition.** Additional segments (Bézier2/Bézier3) and a render mode for untrustworthy values (None/Dashed/Line).
**Acceptance.** UI: switching the segment changes the smoothing; bad values are drawn according to the chosen mode.

### PN-8 — Pen label/legend (SHOULD)
**Definition.** A legend (detailed view): pen name, current value, value at cursor, scale range. A label at the right edge (Name/Value/Name+Value).
**Acceptance.** UI: the legend shows the current value, value-at-cursor, and range; changing the label mode changes the text at the edge.

### PN-9 — kx+b scaling and formatters (NICE)
**Definition.** A multiplier (k) and offset (b) per pen; value formatters for X and Y (number of digits, exponential / floating-point).
**Acceptance.** Core/test: applying k/b shifts/scales the displayed values; the formatter yields the specified number of digits.

### PN-10 — Point markers and fill (NICE)
**Definition.** A graphical point marker (size/type), a fill of the lower part of the chart, line transparency, a border.
**Acceptance.** UI: enabling markers draws points of the chosen type; fill/transparency are applied visually.

## 4. Cursors and measurement

### CU-1 — Vertical cursor / hover readout (MUST)
**Definition.** A vertical line that follows the mouse; shows the local time and the value of every visible pen at the X point. Implemented as an Avalonia overlay (does not trigger a plot redraw); value reading is a binary search + linear interpolation over `Center`, with gap/out-of-range → empty.
**Acceptance.** Core/test: `CursorReadoutModel` — interpolation between points, null on a gap and out of range. UI: pointer-move does not trigger a ScottPlot redraw; the readout shows the time and the values of the visible pens.

### CU-2 — Read a pen's value at a point (MUST)
**Definition.** At any point of the window the operator sees the numeric value of the selected/all visible pens (see CU-1), including the value interpolated between samples.
**Acceptance.** UI: hovering over an arbitrary X gives the pen's value; on a gap — a "no data" marker.

### CU-3 — T1/T2 markers and delta measurement (MUST)
**Definition.** The operator places two time points T1 and T2 (delta mode: two clicks place the vertical lines, a third click starts a new measurement). The system shows Δt = T2−T1 and Δy for the active pen (the values at T1 and T2 are interpolated; a gap → null). In delta mode a drag does not pan.
**Acceptance.** Core/test: `DeltaCursorModel.Compute` returns `DeltaReadout(Δt, Δy)`; Δy is computed for the active pen with interpolation. UI: two clicks give a "Δt h/m/s, Δy" label; a third click resets.
**Note.** This is a direct user requirement: "place markers T1, T2 … and look at the value". The MasterSCADA reference has no ready-made delta readout — here it is mandatory.

### CU-4 — Multiple named bookmarks (SHOULD)
**Definition.** Beyond T1/T2 — an arbitrary number of time bookmarks with "previous/next" navigation and centering. A bookmark is placed with a double-click in vertical-cursor mode.
**Acceptance.** UI: ≥3 bookmarks are placed; the navigation buttons move the window to them with centering.

### CU-5 — Horizontal cursor and crosshair (NICE)
**Definition.** A horizontal line (a value slice for the active pen) and a crosshair mode (vertical+horizontal at once) showing X and Y in the center.
**Acceptance.** UI: the horizontal cursor shows Y on the active pen's scale; the crosshair displays both coordinates.

### CU-6 — Readout update under the cursor at the live edge (SHOULD)
**Definition.** During a sticky window shift (realtime) the value under a stationary cursor must be recomputed rather than "freeze" until the next pointer-move.
**Acceptance.** UI: in realtime, with the mouse stationary, the readout value updates as new data arrives.
**Note.** Closes gap (b)9 of the current state.

## 5. Data and archive (PostgreSQL)

### DA-1 — The data source is always PostgreSQL (MUST)
**Definition.** The production provider for history and extent is PostgreSQL. The provider contract: `QueryHistoryAsync` (window + target column count), `QueryArchiveExtentAsync` (full range). It returns a `PenHistoryEnvelope` (Min/Max/Center, NaN gaps). Errors flow via `FluentResults`, with no exceptions on the UI thread.
**Acceptance.** DB: against a real PostgreSQL, history load fills the canvas; the extent is pulled from the DB; a dropped connection yields a failed `Result` rather than a UI crash. A stub provider is acceptable only in tests/demos, not in production.

### DA-2 — Archive aggregation layers (MUST)
**Definition.** Layers `Raw/Minute/Hour/Day` mirror the archive layer codes `l = 0..3`. A coarse layer is **not** a set of computed aggregates: the SCADA engine writes a selection of real samples, up to four per period, chosen so that the period's extremes are among them (`scada-archive.md`). Reduction of whatever the chosen layer returns down to the canvas column count is performed on the PostgreSQL-query side, not by reading raw data into the client.
**Acceptance.** DB: a query on a coarse layer returns orders of magnitude fewer rows than Raw and preserves spikes, because each period's minimum and maximum samples are present. Core/test: `AggregationLayer` maps one-to-one onto the archive layer codes and exposes each layer's point spacing (period ÷ 4).

### DA-3 — Automatic layer selection by window width (MUST)
**Definition.** The coarsest layer whose point spacing still fits inside one pixel column is selected, i.e. the largest layer satisfying `window / targetColumnCount ≥ spacing`, where spacing is 15 s for Minute, 15 min for Hour and 6 h for Day. For a 1000-column canvas this puts the boundaries at roughly 4.2 hours, 10.4 days and 250 days. A 10% hysteresis at each boundary prevents chatter.
**Acceptance.** Core/test: `LayerForWidth` — layer transitions at the computed thresholds for a given column count, with hysteresis preventing flicker when the width oscillates around a boundary.

### DA-4 — Manual layer selection (SHOULD)
**Definition.** The operator can pin a layer manually (a combo box + a lock button), overriding the automatic selection. Currently the layer in the toolbar is read-only text; an interactive selector is needed.
**Acceptance.** UI: a manual layer selection applies to queries and is held until the lock is released; on release the automatic selection returns.
**Note.** Closes gap (b)1: there is no manual selector, the layer is only auto-by-zoom.

### DA-5 — Decimation to the canvas width (MUST)
**Definition.** The number of columns ≈ the DataRect width in pixels (256..2048). A min/max-type decimator (M4-like): spikes survive; gaps split the series into segments with NaN anchors (no "collapse to a straight line" at the edges).
**Acceptance.** Core/test: the decimator preserves the global min/max of a bucket; on fragmented data it inserts NaN anchors between segments. UI: on gaps the line breaks rather than being stretched as a straight line.

### DA-6 — Column-count stability under fragmentation (SHOULD)
**Definition.** The final column count must not substantially exceed `targetColumnCount` when there are many short segments (each segment yields ≥1 column → overflow). The distribution of columns across segments must keep the "≈ target" contract.
**Acceptance.** Core/test: over N segments the total column count ≤ target + tolerance; the "≈ target" contract is not grossly violated.
**Note.** Closes gap (b)6.

### DA-7 — X monotonicity at the history↔realtime seam (MUST)
**Definition.** Realtime timestamps must be strictly greater than the last history timestamp. `TrendPenState.AppendRealtime/FoldRealtime` must drop/clamp points with X ≤ the last X (as strictly as `PenHistoryEnvelope`).
**Acceptance.** Core/test: feeding a realtime point with X ≤ the end of history does not produce a "return" of the line (the point is dropped or clamped). UI: at the history/realtime seam the line does not go backward in time.
**Note.** Closes the most real correctness risk (b)7.

### DA-8 — Quality and gaps (SHOULD)
**Definition.** The archive marks a break with `q = 32` on the last sample before it and `q = 16` on the first sample after it; absence of rows without a preceding `q = 32` means the value did not change and the line continues horizontally (`scada-archive.md`). The provider maps a break to a NaN anchor in the envelope along the whole path from PostgreSQL, not only synthetically in the stub. Quality codes outside the good set mark an untrustworthy sample, which is also dropped.
**Acceptance.** DB: a marked break produces a line break, while a long run without rows produces a continuous horizontal line; the readout inside a break is "no data".
**Note.** Closes gap (b)10.

### DA-9 — History query sequencing (MUST)
**Definition.** Gesture re-queries are debounced (Throttle ~150 ms → FromAsync → Switch, latest-wins) and carry monotonic numbering (an old response does not overwrite a newer window). The initial load is awaited directly.
**Acceptance.** Core/test: with two overlapping queries the response with the greater sequence is applied; the stale one is ignored. UI: a fast zoom does not leave the old window on screen.

## 6. Real time

### RT-1 — Realtime stream from PostgreSQL (MUST)
**Definition.** A subscription to new data with batching (Buffer ~100 ms on the data scheduler → assemble a union timeline → ObserveOn the UI scheduler → RefCount). The realtime buffer is bounded (cap ~100k points).
**Acceptance.** Core/test: a batch assembles a union over distinct timestamps; per-pen values with null=gap. UI: new points appear in batches, the buffer does not grow without bound.

### RT-2 — Auto-scroll / live-edge mode (sticky) (MUST)
**Definition.** Sticky mode keeps the right edge of the window at "now"; when the live edge leaves the window (a manual pan) sticky auto-detaches. A "go to data now" button/command returns sticky.
**Acceptance.** Core/test: `TrendNavigationModel` auto-detaches sticky when the live edge leaves the window; jump-to-now restores it. UI: in realtime the window rides the data, a manual shift stops the follow.

### RT-3 — Folding realtime on coarse layers (SHOULD)
**Definition.** On coarse aggregation layers realtime folds into the last column (`FoldRealtime` widens Min/Max) rather than drawing raw points over the aggregate.
**Acceptance.** Core/test: feeding a point on a coarse layer widens the Min/Max of the last column without adding a new raw point.

### RT-4 — Update/render parameters (NICE)
**Definition.** A data-update interval, pixel-aware thinning, a redraw FPS cap (overlay reposition from a throttled RedrawRequested ~30 FPS).
**Acceptance.** UI: redraw is no more frequent than the given FPS; pointer-move does not initiate a full plot redraw.

## 7. Miscellaneous

### MS-1 — Panel visibility control (SHOULD)
**Definition.** Panel-visibility toggles: Charts, Legend, (later) Values/Messages, Settings — with hotkeys.
**Acceptance.** UI: a toggle hides/shows the corresponding panel; a hotkey duplicates the button.

### MS-2 — Grouping/sorting/drag-add of pens in the legend (SHOULD)
**Definition.** The pen panel/legend: grouping (by source / by scale / none), sorting, adding a pen by dragging a variable from the source tree (and rebinding the source).
**Acceptance.** UI: dragging a variable adds a pen; changing the grouping rebuilds the list.

### MS-3 — Coordinate grid (NICE)
**Definition.** A configurable grid: types (Auto/Static/Floating/Multiple), visibility of the major/minor/mini grid, transparency, line thinning.
**Acceptance.** UI: changing the grid type and visibility changes the grid rendering.

### MS-4 — Pen setpoints (control limits) (NICE)
**Definition.** Setpoint lines (upper/lower, alarm/warning) for the active pen; user and parametric setpoints; color indication of a limit breach.
**Acceptance.** UI: setpoints are shown for the active pen; a user setpoint is added and held.

### MS-5 — Computed pens (processings) (NICE)
**Definition.** Processing pens: mathematical (ln/lg/exp/derivative/integral), filters (moving average, RMS), operations between two charts (sum/difference/Y=F(X)/correlation). A processing is itself a pen.
**Acceptance.** Core/test: a processing over a source pen yields the correct result on a reference input; it renders as an ordinary pen.

### MS-6 — Export / print / snapshot (NICE)
**Definition.** A screenshot of the canvas, export of values (CSV) and messages (HTML), printing. Marked `[LATER]` — outside the near-term scope.
**Acceptance.** UI: a snapshot saves a raster file; value export yields a CSV with correct time/pen columns.

### MS-7 — Complexity levels / access rights (NICE)
**Definition.** Profiles of UI-element visibility (minimal/basic/advanced) and binding of operations to operator rights.
**Acceptance.** UI: changing the level changes the set of visible elements; an operation under a right is unavailable without that right.

## Priority summary

**MUST (product core):** TM-1, TM-2, TM-3, TM-4; AY-1, AY-2, AY-3, AY-4; PN-1, PN-2, PN-3, PN-4, PN-5, PN-6; CU-1, CU-2, CU-3; DA-1, DA-2, DA-3, DA-5, DA-7, DA-9; RT-1, RT-2.

**SHOULD:** TM-5, TM-6; AY-5, AY-6; PN-7, PN-8; CU-4, CU-6; DA-4, DA-6, DA-8; RT-3; MS-1, MS-2.

**NICE:** TM-7, TM-8; AY-7; PN-9, PN-10; CU-5; RT-4; MS-3, MS-4, MS-5, MS-6, MS-7.

**Direct user requirements (all MUST):** continuous time canvas → TM-1; multiple Y axes → AY-1/AY-2; resize a pen's Y layer, min/max, disable → PN-2/PN-3/PN-4; T1/T2 markers → CU-3; pen value at a point → CU-2; source always PostgreSQL → DA-1.

**Known "model exists — UI missing" discrepancies promoted to requirements:** AY-6 (log axis), AY-5 (autoscale-to-window), DA-4 (manual layer), AY-2 (AxisKey ≠ group), DA-7 (X monotonicity), CU-6 (readout at the live edge), DA-6 (column-count stability).
