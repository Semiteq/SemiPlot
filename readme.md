[![CI](https://github.com/Semiteq/SemiPlot/actions/workflows/ci.yml/badge.svg)](https://github.com/Semiteq/SemiPlot/actions/workflows/ci.yml)
![C#](https://img.shields.io/badge/C%23-.NET-blue)

SemiPlot — приложение для просмотра графиков и трендов технологических параметров промышленных установок. Использует SimpleScada как источник данных.

## Возможности

**Тренд-вьювер**

- Перья (источники данных): добавление/удаление на лету, включение/выключение, логическая группировка
- Мультиоси: у каждого пера своя шкала min/max; на графике стоит ось активного пера, всегда слева
- Курсор/перекрестье с чтением значения **всех** видимых перьев в точке
- Минилегенда: чекбокс / цветная точка / имя / текущее значение в маске пера / единица измерения;
  перо может стоять в нескольких группах и показывается под каждой, панель сворачивается до
  чекбокса, точки и имени
- Переключатель в заголовке каждой группы включает или выключает все её перья разом. У него три
  состояния: все включены, все выключены и смешанное, когда включена только часть
- Ширина панели легенды меняется перетаскиванием ручки между графиком и панелью, в развёрнутом и
  свёрнутом виде. Каждый вид помнит свою ширину до конца сеанса, после перезапуска ширина сбрасывается
- Стартовый набор: при открытии рисуются только перья, помеченные в каталоге как включённые
- Границы шкалы из каталога: перо открывается ровно на них, без полей; правки оси живут до конца
  сеанса и в базу не уходят
- Слои агрегации архива: raw / минута / час / сутки — слой выбирается по ширине окна и ширине холста
  вместе (самый грубый слой, шаг которого укладывается в пиксельную колонку)
- Навигация по времени: зум/пан, переход к началу/концу, выбор диапазона
- Реалтайм и история через единый интерфейс `IDataProvider`

**Окно**

- Меню «Файл / Правка / Вид / Справка»: выход, окно настроек, переключатели панели навигации,
  легенды, миникарты и панели сообщений, окно «О программе» с версией сборки и каталогом конфигурации
- Окно настроек («Правка → Настройки»): язык, тема и подключение к архиву, включая пароль. Окно
  пишет в файлы конфигурации только изменённые ключи, и каждый попадает в тот файл, где уже лежит.
  Перед записью значения проверяются теми же загрузчиками, что и на старте; негодное значение до
  файла не доходит, а отказ появляется в панели сообщений. Изменения вступают в силу при следующем
  запуске. Часовой пояс архива окно не показывает: он остаётся в `connection.yaml` и переживает
  любую перезапись файла. Комментарии в переписанном файле не сохраняются
- Настройки открываются и из окна ошибки старта: там их открывают чаще всего, потому что поставляемый
  набор приходит с пустым паролем
- Панель навигации: переход к живому краю, режим слежения, режим дельта-курсоров
- Строка состояния: связь с архивом и активный слой агрегации, оба на языке окна. Индикатор связи —
  кнопка, она же открывает и закрывает панель сообщений
- Панель сообщений: список отказов с отметкой времени и счётчиком повторов, не длиннее 200 записей.
  Туда приходит каждый отказ — чтение архива, потеря связи и необработанное исключение ReactiveUI

## Архитектура

- **Платформа:** .NET 10, C# 14, Windows
- **Оболочка:** Avalonia 12.0.5 (Win32 + Skia + HarfBuzz) + ReactiveUI
- **Графика:** ScottPlot.Avalonia 5.1.59 (нативный рендеринг, SkiaSharp)
- **Данные:** абстракция `IDataProvider`; единственная реализация — `PostgresDataProvider`,
  который читает архив PostgreSQL от Simple-Scada 2: каталог переменных, границы архива,
  окно истории и опрос живого края (см. документацию)

Подробно — в `docs/architecture/` (overview, charting, trend-interaction, data-integration).

## Требования

| Компонент       | Требование                                                    |
| --------------- | ------------------------------------------------------------- |
| ОС              | Windows 10 или Windows 11 (64-bit)                            |
| Среда сборки    | .NET 10 SDK                                                   |
| Источник данных | Архив PostgreSQL от Simple-Scada 2, подготовленный SemiBase `v0.4.0` или новее: нужна роль `semiplot` и таблицы каталога `semiplot_tags`, `semiplot_groups`, `semiplot_pen_groups`. Версию разметки программа не проверяет: на более ранней разметке падает чтение каталога перьев, и окно ошибки старта называет недостающий столбец или таблицу. Без архива приложение показывает ошибку старта в главном окне вместо графика |
| Конфигурация    | Каталог `--config-dir` с папками-секциями `app/` и `connection/`. Папка секции читается целиком: каждый `*.yaml` в ней разбирается отдельно, а ключи сливаются в одно отображение; ключ, который лежит сразу в двух файлах одной папки, роняет старт и называет оба. Поставляемый набор лежит в репозитории в `ConfigFiles/`; запускать надо по его копии (`SemiPlot/Artifacts/dev-config`, туда же смотрят конфигурации запуска из `.zed/` и `.run/`), в отслеживаемые файлы ничего не вписывают. `app/app.yaml` держит `locale` (`ru` \| `en`) и `theme` (`light` \| `dark`), оба обязательны и без значений по умолчанию; `connection/connection.yaml` — подключение к архиву, и `password` в нём пустой. `host` принимает только IPv4-адрес вида `127.0.0.1`, а имя сервера, `localhost` в том числе, роняет старт. Пароль заполняют в окне «Правка → Настройки», которое открывается и из окна ошибки старта. Любая из этих ошибок открывает окно ошибки старта вместо графика |
| Ключи запуска   | `--config-dir`, `--log-file` и `--logging-level` обязательны, значений по умолчанию нет ни у одного. `--logging-level` принимает `verbose`, `debug`, `info` (или `information`), `warning`, `error`, `fatal`. Пропущенный ключ, незнакомый ключ, ключ с пустым значением и негодный уровень логирования открывают окно ошибки старта и дают код возврата 1 |
| Тестовый стенд  | Только для интеграционных тестов: Docker (или иная среда контейнеров). `semibase` приходит слоем образа из `ghcr.io/semiteq/semibase`, ставить его на машину не нужно; без среды контейнеров эти тесты падают, а не пропускаются |

## Сборка и запуск

```powershell
# Сборка
dotnet build SemiPlot/SemiPlot.UI/SemiPlot.UI.csproj

# Запуск. Все три ключа обязательны, см. "Требования".
# Запускаем по копии набора, а не по отслеживаемому. SemiPlot\Artifacts\ лежит в .gitignore,
# а %TEMP%\SemiPlot принадлежит демо-стенду, который чистит его на старте.
New-Item -ItemType Directory -Force SemiPlot\Artifacts\dev-config | Out-Null
Copy-Item ConfigFiles\* SemiPlot\Artifacts\dev-config -Recurse -Force

# В connection.yaml пароль пустой, поэтому первый запуск открывает окно ошибки старта.
# Там "Правка -> Настройки": вписать пароль, сохранить, закрыть вьювер и запустить снова.
dotnet run --project SemiPlot/SemiPlot.UI/SemiPlot.UI.csproj -- `
  --config-dir SemiPlot\Artifacts\dev-config `
  --log-file SemiPlot\Artifacts\dev-logs\semiplot.log --logging-level information

# Тесты
dotnet test SemiPlot.slnx
```

Хуки живут в `.githooks/` и подключаются один раз на клон: `git config core.hooksPath .githooks`. Хук
запрещает коммит прямо в `master` или `main`. Дальше он проверяет только проиндексированные `.cs`:
`dotnet format --verify-no-changes` и линтер комментариев `terse` (закреплён в
`.config/dotnet-tools.json`, хук сам делает `dotnet tool restore`).
Исходники ASCII, без BOM; файл из `dotnet new` проходит хук только после
`dotnet format SemiPlot.slnx --include <file>`.

Демо-стенд с одноразовым архивом и живой записью поднимается одной командой:
`dotnet run --project SemiPlot/SemiPlot.AppHost` — контейнер PostgreSQL, `converge`, писатель и
вьювер стартуют в порядке зависимостей и останавливаются вместе (см. `docs/architecture/bench.md`).
Стенд работает с копией: он кладёт `ConfigFiles/` в `%TEMP%\SemiPlot\ConfigFiles`, пишет лог в
`%TEMP%\SemiPlot\Logs` и убирает копию конфигурации на остановке. Логи чистятся при следующем
старте, потому что вьювер ещё может держать `semiplot.log` открытым. В отслеживаемый набор ничего
не пишется.

Весь проект `SemiPlot.Tests.Integration` — тесты стенда и сквозные сценарии — поднимает PostgreSQL
в контейнере. Образ стенда собирается из `SemiPlot/bench/Dockerfile`:
он забирает `/semibase` из `ghcr.io/semiteq/semibase:latest` и выполняет `semibase bench` из
`/docker-entrypoint-initdb.d/` — до того, как откроется опубликованный порт. Отдельный бинарник
`semibase` на машине не нужен: `dotnet test SemiPlot.slnx` запускает эти тесты сам.

Прогон ничего после себя не оставляет: собранный образ стенда, контейнер, шаблонная база и все её
клоны удаляются вместе с прогоном. Скачанные из реестра образы (`postgres:17-alpine`,
`ghcr.io/semiteq/semibase:latest`) остаются — намеренно; тег `latest` фикстура подтягивает перед
сборкой образа.

Если контейнерной среды нет, тесты **падают**, а не пропускаются: фикстура пробрасывает ошибку, и
xunit заваливает всю коллекцию с `TestPipelineException`. `dotnet test SemiPlot.slnx` на такой
машине красный, а зелёным остаётся только `SemiPlot.Tests.Unit`.
