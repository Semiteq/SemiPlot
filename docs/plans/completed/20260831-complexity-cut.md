# Complexity Cut

## Overview

Remove the over-engineering, dead defensive machinery and duplicated rationale the repository carries,
while keeping what the operator sees on a healthy archive: the same chart, the same startup error window
titles, details and remedies, the same live-edge banner, the same bench and the same seeder command line.

The cut lands as nine pull requests, each one logical change on its own branch off `origin/master`,
merged before the next starts. Every slice leaves the full solution building and the full suite green,
and updates the architecture documents it invalidates, so `master` never carries a document describing
a deleted type.

Operator-visible changes, all deliberate:

| Change | Where |
| --- | --- |
| The startup health row for a non-empty default partition is gone; the state is written and fixed on the SCADA side | slice 1 |
| The `57014` remedy names `statement_timeout` for the reader role without quoting its value | slice 1 |
| `connection_file_version` in `archive-connection.yaml` is ignored rather than required | slice 1 |
| A `--breaks` plan that would leave a single-point run is rejected instead of receiving a synthesised stop row | slice 7 |
| The seeder's usage text is generated by `System.CommandLine`; flag names and meanings are unchanged | slice 6 |

## Development Approach

- **testing approach**: Regular. The 707 existing tests are the safety net; each task deletes the tests
  of what it removes, rewrites the tests of what it reshapes, and adds a test only where a new behaviour
  appears.
- one slice equals one branch and one pull request whose description needs no "and"; a slice starts
  only after the previous one is merged and `master` pulled
- every code task ends with `dotnet build SemiPlot.slnx` and the tests of the projects it touched;
  every slice close runs `dotnet test SemiPlot.slnx` with Docker running
- every task that touches code also touches the tests of that code in the same task
- update this plan file when scope changes during implementation
- `dotnet format SemiPlot.slnx` before every commit
- commit messages follow `<type>(<scope>): <description>`; every commit in a slice belongs to that
  slice's scope

## Testing Strategy

- **unit tests**: `SemiPlot.Tests` (UI, Core models), the pure half of `SemiPlot.Tests.Data`
- **gated tests**: the container half of `SemiPlot.Tests.Data` and all of `SemiPlot.Tests.Journeys`;
  they run locally against Docker and in CI with `SEMIPLOT_REQUIRE_DB=1`
- **end-to-end**: `SemiPlot.Tests.Journeys/LiveEdgeArchiveJourneyTests.cs` drives startup, initial

## Solution Overview

| Slice | Branch | One logical change |
| --- | --- | --- |
| 1 | `error-plane-collapse` | One `ArchiveError` and one `ConnectionFileError` type; the two cold-path readers, the health row and the connection-file version go with the arms that served them |
| 2 | `int-pen-ids` | Pen identifiers are `int` end to end |
| 3 | `provider-wrappers` | `NpgsqlDataSource` registered directly, `PenLineStyleReader` inlined, dead package references removed |
| 4 | `single-history-path` | The initial history request goes through the debouncer; the flag cluster goes |
| 5 | `ui-platform-duplicates` | Generated `InitializeComponent`, DI factories replaced by direct construction, single-use wrappers and platform duplicates removed |
| 6 | `seeder-cli` | `System.CommandLine` replaces the hand-rolled parser and `FluentResults` leaves the seeder |
| 7 | `seeder-generator` | Generator pinned by invariants instead of a digest; follow start computed on the lattice without the millisecond step; short break runs rejected |
| 8 | `harness-provisioner` | Provisioner pinned by digest in the Dockerfile; Docker Engine API and harness self-tests removed |
| 9 | `comment-audit` | Comments cut to one-line invariants; architecture documents compressed |

Slices 1 to 5 depend on each other in order (3 uses the mapper shape of 1; 4 and 5 touch files 2
renames). Slices 6, 7, 8 are independent of 1 to 5 and of each other; 9 runs last.

Key decisions:

- **Error types collapse to two records keyed by an enum.** `ArchiveError(ArchiveFault Kind, string Host,
  int Port, string Database, string Detail)` and `ConnectionFileError(string Path, ConnectionFileProblem
  Kind, string Reason)`, both deriving `FluentResults.Error`. `Detail` carries the one per-kind value the
  old subclasses held. The mapper switches on `Kind`; the coverage test enumerates the two enums and
  asserts no member maps to `GenericTitle`. Tests over provider errors keep asserting on type and field,
  never on message text; the field is `Kind`.
- **`57014` maps to a fixed remedy.** No second connection on the failure path.
- **The default-partition check goes away entirely.** No `EXISTS`, no banner row, no log line.
- **Pen identifiers are `int`.** The archive column is `int4`; the widening and the range-tested
  narrowing are self-inflicted.
- **The initial history request is an ordinary request.** `RequestInitialHistory` keeps its empty-
  catalogue guard and its window bookkeeping and calls `RequestHistory`; `Switch()` in the debouncer is
  the one latest-wins mechanism. The `Throttle` window costs 150 ms on the first paint.
- **`AddUi()` stays, its factories go.** `CLAUDE.md` names the method; the two `Func<...>` registrations
  are the indirection. `App.InitializeServices` constructs the chart and minimap view models directly
  with loggers from the container.
- **Follow start is lattice arithmetic.** `LiveTailGenerator.Generate(options, afterExclusive,
  toExclusive)` takes the archive edge and starts at the next lattice index, so `StaleArchiveGuard`
  keeps its five-minute age bound (the cap on the backfill `scripts/bench-demo.ps1` relies on) and loses
  `StartFrom`. `RawLayerGenerator.AppendWindow` is unchanged; the seed path and its `COPY` are unchanged.
- **`CoarseFlush` stays.** Its SQL is a server-side aggregate over a period the client must not read
  back, and its open-period rule is a distinct behaviour `LayerThinner` does not express;
  `CoarseFlushTests` is the correct guard on the two agreeing.
- **Generator invariants replace the golden digest.** Determinism (two `Generate` runs with the same
  options are sequence-equal), lattice alignment, marker pairing and per-pen row counts are pinned; the
  waveform itself is not. `CLAUDE.md` and `bench.md` are rewritten to say so.
- **The provisioner stays on `latest`, pulled through the docker CLI.** A delivered installation
  updates only the provisioner, so the pair worth testing is the newest `semibase` with the current
  reader; a digest pin would test a pair nobody ships. `DockerCli.PullProvisionerAsync` runs
  `docker pull ghcr.io/semiteq/semibase:latest` ahead of the build and tolerates a failed pull with one
  stderr line, which replaces the `Docker.DotNet` resolver, the resolution record and the
  `--version` exec. The readiness wait and the
  SHA-256 image tag stay: the first names a provisioning failure, the second keys the built image to a
  base reference that may be registry-qualified.
- **`_creationGate` stays.** One `SemaphoreSlim` line is cheaper than a convention a future gated class
  can miss.
- **Each slice updates the documents it invalidates.** Slice 9 then does the repository-wide comment
  audit and compresses the architecture documents that restate code.

## Technical Details

### `ArchiveFault`

```csharp
public enum ArchiveFault
{
	Unreachable,        // socket, TimeoutException, NpgsqlException without SQLSTATE; Detail empty
	AccessDenied,       // 28P01, 28000, 42501; Detail = username
	DatabaseMissing,    // 3D000; Detail empty
	TableMissing,       // 42P01; Detail = relation the failing statement touches
	ShapeUnexpected,    // 42703; Detail = server MessageText
	QueryTimedOut,      // 57014; Detail empty
	ConnectionLost,     // raised by RealtimePoll after three failed ticks; Detail = "3"
	ReadFailed          // any other SQLSTATE, or a client-side throw; Detail = SQLSTATE or empty
}
```

`ConnectionFileProblem` gains `NotFound` and loses `VersionMismatch`.

### History request path after slice 4

```
RequestInitialHistory (guard: pens exist; stores window) ──┐
gesture / resize ──────────────────────────────────────────┼──► _historyDebouncer.Request ──► Throttle ──► Switch ──► ApplyHistory
```

`HistoryRequest` loses `Sequence`; `NavigationWindow` loses `IsColumnCountChange`; `ApplyHistory`
takes `(IReadOnlyList<PenHistoryEnvelope> envelopes, IReadOnlyList<int> requestedPenIds)`.

### Seeder command line after slice 6

Same flags as today so `scripts/bench-demo.ps1` and the `CLAUDE.md` "Build" invocation keep working
unchanged. One `RootCommand` with typed `Option<T>`s and validators; `--follow` present selects follow
mode. Validators run before the handler builds `SeederOptions`, so `Start` is never computed from an
unchecked `Days` and the `ArgumentException` catch in `Program.cs` has nothing left to catch.
ASSUMPTION: `System.CommandLine` 2.0.x is stable on NuGet at implementation time; pin the latest 2.0.x
in `Directory.Packages.props`. The exact flag set is read off `SeederOptions.Usage`, `FollowOptions.Usage`
and every seeder invocation in `scripts/bench-demo.ps1` in the first task of the slice.

### Follow start after slice 7

```
edge = SELECT max(t) FROM public.trends WHERE l = 0          (StaleArchiveGuard.CheckAsync, unchanged)
firstIndex = floor(edge.Ticks / intervalTicks) + 1
LiveTailGenerator.Generate(options, afterExclusive: edge, toExclusive: now)
    → RawLayerGenerator.AppendWindow(from: firstIndex * intervalTicks, to: now)
```

No `+1 ms`, no `StartFrom`. The `t > edge` bound is what `RealtimePoll` already uses on the read side
(`ArchiveStatements.RealtimePoll`).
