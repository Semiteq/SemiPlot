# Pick a pen on the plot

Issue: #70.

## Overview

- A left click on a drawn line makes that pen active. Today the active pen is chosen only from the sidebar
  (`Legend/TrendLegendRowViewModel.cs:56` calls `TrendChartViewModel.SetActivePen`), and the chart holds no hit
  test of any kind. `docs/architecture/trend-interaction.md` ("Many-axes management") and
  `docs/architecture/trend-feature-spec.md:108-110` (PN-6, MUST) both require the click.
- The active pen is drawn 2 px wide and above every other pen; every other pen stays 1 px.
- A press that travels no further than the click slop before release is a click: it picks a pen and does not
  pan. A press that travels further pans exactly as today and picks nothing. Delta mode and the axis-region
  press never pick.

## Solution Overview

- **Distance to what the operator sees.** The hit test builds the pen's path over the same
  `VisibleRange(columns, XAxis.Min, XAxis.Max)` that `Render` uses, projects every vertex with the same
  projection, and takes the minimum pixel distance from the click to each stroked segment. Because the range is
  the same, `Build` picks the same entry edges and the vertices are exactly the drawn ones. A tall envelope
  column is a vertical stroke, so a click anywhere on the band hits it; stepped and interpolated pens, gaps
  and the log10 floor come out right for the same reason. A lone vertex after a gap is never stroked, so it is
  never hit. ScottPlot clips every plottable to the data area, so the hit test clips each segment to the data
  rectangle and ignores a click outside it. The cost is one walk of the visible columns per pen per click, off
  the frame path.
- **One choice rule.** Among the visible pens within 6 px of the press point, the nearest wins; on an equal
  distance the active pen wins, otherwise the first in catalogue order. No pen within 6 px means no change.
- **Click versus drag.** The press still routes through `ChartPressRouter.Route`; the pan branch becomes
  `ChartPressAction.PanOrPickPen`. The press captures the pointer, calls `BeginDrag` and stores `_dragOrigin`
  as today. A move pans only once `ChartPressRouter.IsPastClickSlop(_dragOrigin, current)` is true (Euclidean
  distance over 4 px); until then `_dragOrigin` stays the press point, so the first pan covers the whole
  distance and no movement is lost. The release reads the decision and the press point into locals before
  `Capture(null)`, because that call runs `EndDrag` through `PointerCaptureLost` and clears the state. A
  release before the slop is crossed picks at the press point, which is where the operator aimed. A lost
  capture never picks.
- **Emphasis on every change of the active pen.** A private `EmphasizeActivePen()` in the view model runs at
  the end of `SetActivePen` (when it accepts the pen), `SetPenVisibility` and the catalogue apply. It takes
  `lock (Plot.Sync)` around `_penSet.Emphasize(ActivePenId)` and nothing else; the `ActivePenId` write,
  `ApplyAxisModel` and every notification stay outside the lock. In the catalogue apply it runs inside the
  existing lock block, which already delays notifications. `ChartPenSet.Emphasize` raises nothing: it sets each
  line's width (2 px active, 1 px otherwise) and calls `_plot.MoveToTop` on the active line. The active pen
  then also draws over the delta cursor lines where they cross, which every pen added after the view loaded
  already does.

## Technical Details

- `EnvelopePath.SegmentDistance(Pixel start, Pixel end, Pixel point)`: distance from `point` to the segment,
  a degenerate segment measured to its point. `EnvelopePath.ClippedSegmentDistance(Pixel start, Pixel end,
  Pixel click, PixelRect bounds)` first clips the segment to `bounds` (Liang-Barsky, no allocation) and returns
  `double.PositiveInfinity` when nothing of it is inside. Pure, no Skia.
- `EnvelopeLine`:
  - a private per-vertex projection helper holds the math `Render` uses at `:95-103` (the log flag, the pinned
    floor, `GetPixel`); `Render` keeps streaming into `SKPath` through it, with no extra list pass per frame.
  - `internal double DistanceTo(Pixel click, PixelRect dataRect)` runs on the UI thread and returns
    `double.PositiveInfinity` for a click outside `dataRect`. Under `_renderStateLock` it takes `VisibleRange`
    over the X axis limits and `Build`s into a list of its own (never `_pathPoints`, which the render thread
    owns); outside the lock it projects each vertex through the helper and returns the minimum
    `ClippedSegmentDistance` over stroked segments, so a line the data-area clip hides is never hit.
  - `internal SetLineWidth(float width)` writes a `_lineWidth` field under `_renderStateLock`; `Render` copies
    it into `_stroke.Width` beside `_stroke.Color`. No getter. `DefaultLineWidth = 1f` and
    `ActiveLineWidth = 2f` are internal constants here.
- `ChartPenPick.Choose(IEnumerable<(int PenId, double Distance)> candidates, int activePenId)` returns `int?`,
  with a private `PickTolerancePixels = 6`. Pure and static, in `Chart/ChartPenPick.cs`, like
  `ChartPressRouter`.
- `ChartPenSet`:
  - `int? PenNearest(Pixel click, PixelRect dataRect, int activePenId)` measures each visible pen in catalogue
    order and calls `ChartPenPick.Choose`.
  - `Emphasize(int activePenId)` as above, reading both widths from `EnvelopeLine`.
- `TrendChartViewModel.PickPenAt(Pixel click)` returns nothing: it reads `Plot.LastRender.DataRect`, calls
  `_penSet.PenNearest` and hands a result to `SetActivePen`, which already requests the redraw.
- `ChartPressRouter.IsPastClickSlop(Point origin, Point current)` with `ClickSlopPixels = 4`. The view keeps
  `_dragOrigin` and adds one `_panStarted` flag; `EndDrag` clears both. The release handler runs on the tunnel
  route and returns early for a release whose `InitialPressMouseButton` is not the left button.
