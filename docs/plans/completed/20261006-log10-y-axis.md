# Log10 Y axis

## Overview

A pen can be drawn on a log10 Y axis (#72, spec AY-6, `docs/architecture/trend-feature-spec.md:74-77`).
Pressure spans several decades and shares a screen with pens that do not; on a linear axis one of them
is unreadable.

A pen setting is either live or a start value. A live setting (name, unit, mask, colour, line style)
changes a running chart at the next catalogue read. A start value is what a pen opens with in a new
window and what "Restore initial scale" goes back to; editing on the chart changes the current view
of that window only, and a changed start value never changes a chart already open. The axis type is a
start value, like the start scale pair:

- **Stored per pen** as `semiplot_tags.log_scale_on_start`
  (`SemiBase/docs/plans/20261006-on-start-columns.md`), edited in the pen editor as a table column
  and a form checkbox.
- **Switched per window** by a checkbox in the axis scale panel, for the session of that window.
  "Restore initial scale" restores the stored type with the stored bounds.
- **Rendered logarithmically**: majors and minor gridlines on log positions, the line projected
  through the same transform, readable ticks over a range narrower than a decade.
- **Non-positive samples are pinned** 2 px above the bottom of the data area. The line stays
  continuous; the cursor and hover readouts show the true value (`0`).
- **Major labels go through `PenValueFormat.Format` with the pen's mask.** A pen spanning decades
  carries an exponent mask such as `0.0E+0`, which `PenValueFormat` accepts
  (`SemiPlot/SemiPlot.Core/Trends/PenValueFormat.cs:99-102`).

The minimap stays linear (`docs/architecture/trend-interaction.md:419-424`). The delta readout stays
a linear difference.

The start scale pair takes the same suffix first: `scale_min`/`scale_max` become
`scale_min_on_start`/`scale_max_on_start` in SemiBase, and every C# member named for the stored pair
follows. That rename is its own pull request ahead of the feature.

## Solution Overview

**The transform lives at the render edge; Core keeps data units.** `PenScale.Min`/`Max`, the panel's
seeded bounds, `ScaleRangeForPen` and every readout stay in the pen's own units. Two places convert:

- `ChartAxisBinder.Apply` sets the axis limits to `log10(Min)`, `log10(Max)`, gives a log axis a
  `LogTickGenerator`, and gives a linear one its stock generator back.
- `EnvelopeLine.Render` projects `log10(y)` while its axis carries a `LogTickGenerator`, and a sample
  `<= 0` at the pinned floor.

Feeding `log10` columns at load is rejected: the cursor, hover and delta readouts read stored values
and would all need the inverse. A custom `IYAxis` is rejected: the plot's axis panels, layout and
grid are built around ScottPlot's own axis types, and the render-edge transform touches two classes.
The stock `NumericAutomatic` log recipe is not enough, because it labels integer decades only.

**The axis type has one home on the render side: the axis's tick generator.** `EnvelopeLine` derives
its mode from `Axes.YAxis.TickGenerator is LogTickGenerator` once per `Render`, together with the
limits, so the line has no flag of its own to drift from the axis. The binder switches a type (limits,
generator, grid minor width) under `lock (_plot.Sync)`, so no frame sees log limits with a linear
generator. The switch happens on a toggle, not on every pan step; the existing limit updates within
one type stay as they are.

**The math is renderer-agnostic and unit-tested in Core** (`AGENTS.md`, "ScottPlot is a thin render
target"): one file, `LogAxis.cs`, holds the projection and the tick choice. `PenScaleModel` pads a
log range in log space in a private method. The UI's `LogTickGenerator` adapts the tick choice to
`ITickGenerator` and labels majors.

**The session flag has the writers the session bounds have.** `PenScaleSettings.IsLogarithmic` is
written by `ChartPenSet.Add` and `RestoreInitialScale` from `Pen.LogScaleOnStart`, and by the panel's
command through `TrendChartViewModel.SetLogarithmic`. A catalogue revision does not write it.

## Technical Details

**`LogAxis` (`SemiPlot.Core/Trends/LogAxis.cs`)**

- `double Project(double value, double floor)`: NaN stays NaN (a gap stays a gap); `value > 0` gives
  `Math.Max(Math.Log10(value), floor)`, so a positive value under a manual minimum lands on the floor
  beside zero instead of below the data area; otherwise `floor`.
- `bool AdmitsMinimum(double? minimum)`: no minimum or one above zero. The panel, the chart's
  `SetLogarithmic`, the pen form and `SanitizeManualRange` read this one rule.
- `IReadOnlyList<LogTick> Ticks(double minLog, double maxLog, double pixelLength)`, `LogTick(double
  Position, bool IsMajor)`, ascending, every position inside `[minLog, maxLog]`:
  - empty for a non-finite bound, `minLog >= maxLog` or `pixelLength <= 0`;
  - majors: of the families below with at least two majors and no gap under 40 px
    (`gap * pixelLength / (maxLog - minLog)`), the one with the most majors, ties going to the
    earlier one. "The first family in this order" was dropped in task 2: over 2..50 at 400 px the
    linear family gives 20 and 40 only and leaves the decade 2..20 without a major, where 1-2-5
    gives 2, 5, 10, 20, 50:
    1. linear: one step in value space, the smallest 1-2-5 step whose narrowest gap, at the top of
       the range, clears 40 px. The gap is computed in closed form,
       `log10(top / (top - step))`, so no step is tried by generating its ticks;
    2. mantissas 1, 2, 5 in every decade;
    3. decades with the smallest stride of 1, 2, 3, 5, 10, 20, ... that clears 40 px.
    If no family has two majors, the two range ends are the majors;
  - minors: decades with stride 1 take mantissas 2..9; a larger stride takes the skipped decades;
    the 1-2-5 family takes the mantissas it skips; the linear family takes four even steps per
    interval, the partial intervals at both ends included;
  - no call builds a list longer than `pixelLength / 40 + 2` majors plus their minors.

**`PenScaleModel` log padding** (private): `lo = log10(min)`, `hi = log10(max)`,
`pad = (hi - lo) * 0.05`, result `(10^(lo - pad), 10^(hi + pad))`; a flat range pads half a decade
each way. `lo`, `hi` and both padded ends stay between decades -307 and 308, so a `+Infinity` sample
or an underflowing exponent never gives the axis a limit of 0 or infinity. `ClampLowerToPositive` is
deleted.

**`LogTickGenerator : ITickGenerator` (`SemiPlot.UI/Chart`)**: `Mask` is set by the binder on every
`Apply` from `pen.Pen.Format`, so a revised mask reaches the labels at the next catalogue read. The
field is written on the UI thread and read on the render thread; a reference write is atomic, and the
field carries the comment naming both threads that `csharp.md` requires.
`Regenerate` maps `LogAxis.Ticks` to `Tick.Major(position, PenValueFormat.Format(10^position, Mask))`
and `Tick.Minor(position)`. A major turns into a minor when its label reads back as zero (a positive
value the mask cannot show), when it does not parse back under the current culture to within 1 % of its
value, or when it equals the last label kept. The rule first written here, "equals its lower
neighbour's", kept a rounded-up label on the lower gridline: over 0.02..0.5 under `0.0` the 0.05 gridline
read "0.1" and the real 0.1 gridline had none. It caches two results keyed on
`(minLog, maxLog, pixelLength, Mask)`, because ScottPlot regenerates each panel at two lengths per
frame; during a pan an auto log range moves every frame and both entries miss, which the per-call
bound above keeps cheap. A published `Ticks` array is never mutated.

**Pinning**: in `Render`, the floor is the axis coordinate of the pixel row 2 px above
`rp.DataRect.Bottom` (`IYAxis.GetCoordinate`), and every Y goes through the axis's own `GetPixel`. The
mode is read once per frame; a type switch holds `Plot.Sync`, which a frame holds too. Under a log axis
`GetAxisLimits` reports X limits only, since the columns are in data units and the axis in decades.

**Gridlines**: when the drawn axis is logarithmic the binder sets
`Grid.YAxisStyle.MinorLineStyle.Width = 1`, otherwise 0. A new opaque palette key
`AppMinorGridLineBrush` (light and dark) feeds `Grid.MinorLineColor` in `ChartPalette.Apply`.
`MinorLineColor` has no getter; a test reads `Grid.YAxisStyle.MinorLineStyle.Color`.

**Stored field**: `Pen.LogScaleOnStart` (default `false`, in `Equals`/`GetHashCode`),
`StoredPen.LogScaleOnStart`, `PenSettingChange.LogScaleOnStart(bool Value)`,
`ArchiveStatements.UpdatePenLogScaleOnStart`, `PenCatalogColumn.LogScaleOnStart = 9`, `Groups = 10`.

**Validation**, one rule and one message in both places: a logarithmic scale needs a minimum above
zero.

- panel: ticking "Logarithmic" on a manual pen whose minimum is `<= 0` is refused; the flag stays
  off and the message line names the rule. The operator applies a positive minimum first, then
  ticks. On an autoscaled pen the tick always succeeds. Apply is disabled while the flag is on and
  the typed minimum is `<= 0`;
- pen form: ticking the flag is refused while the queued pen stores `scale_min_on_start <= 0`; a
  scale draft with a minimum `<= 0` is refused while the flag is on; an empty pair (autoscale)
  passes. The rule joins `RuleOf` and the `IsScaleMinOnStartValid` chain.

`SanitizeManualRange` keeps its clamp for a database row written by hand.
